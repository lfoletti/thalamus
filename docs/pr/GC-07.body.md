## Description

### Problem
The SessionEnd hook writes the transcript payload to `~/.cache/cortexdb/capture-payload.XXXXXX` before the binary can say it has no LLM configured, and removes it only after the capture returns. A hook killed with its session's process group never reaches the `rm`. On a machine running many short automated sessions this leaves one file per session (295 in one morning).

### Fix
- Decline before touching the disk when neither `CORTEXDB_LLM_BASE_URL` nor `CORTEXDB_LLM_URL` is set, the same test `newOrganizeLLM` makes.
- Run the capture as a background child under `wait`, with an `EXIT` trap that removes the payload and `HUP`/`INT`/`TERM` traps that pass the signal on. A shell defers traps while a foreground command runs, so the old shape could not react to a `TERM`.
- Sweep `capture-payload.*` files older than a day on each run, so leftovers from earlier versions disappear on their own.

Nothing changes when an LLM is configured and the capture completes: the same binary runs with the same arguments.

### Tests
- `sh -n` on the launcher.
- Run by hand in a scratch `XDG_CACHE_HOME` with a stand-in binary: (1) no `CORTEXDB_LLM_*` set: no file is written at all; (2) LLM set, capture completes: the payload exists during the capture and is gone after; (3) LLM set, `TERM` sent to the detached capture: the payload is gone and the binary is stopped; (4) a `capture-payload.*` file older than a day is removed on the next run.
- No Go change; `go test -race ./...` passes on `main`.

Part of a small series on running one CortexDB server for several teams (see discussion #66, item GC-07). Each PR stands alone.
