### Changes since review (20 October 2026)

Each point has a test that was written first and fails without the change (`pkg/cortexdb/review_review_test.go`).

1. **The hybrid path.** The gate is applied where #76 now applies the expiry: on the seeds of a hybrid search, on `search_text`, on the chunk tools, on `expand_graph` and on every lane of `cortex_query`. Under `WithReviewGate`, with an embedder, a proposed document is out of `hybrid`, `recall`, `build_context_pack`, `search_text` and the three lanes of `cortex_query`; the accepted twin is served (`TestTheReviewGateHoldsOnTheVectorPath`).
2. **Who reviews.** When a key made the call, `reviewed_by` of a decision is that key, whatever the client wrote: a client under the key `hermes` that sends `reviewed_by: zeus` stores `hermes`, on `ingest_document`, `knowledge_save`, `knowledge_update`, `memory_save` and `memory_update`. Without a key (embedded library), the text given is kept (`TestTheReviewerIsTheKeyThatDecided`).
3. **No silent clearing.** A write that says nothing about the review leaves the decision as it was: a `knowledge_update` that touches other metadata, a `knowledge_save` and an identical or changed re-ingest all carry the status, the reviewer and the date over. A write that sets `review_status` empty on a reviewed row is refused ("cannot be cleared"); a status that is not a string is refused on a memory rather than read as none (`TestAReviewDecisionIsNotClearedSilently`).
4. **Acceptance keeps the rest.** A `knowledge_update` that decides on the review (its metadata names `review_status`) is merged into the stored metadata rather than replacing it: an acceptance that names only the three review keys keeps `expires_at`, `content_sha256`, the chunking and the client's own keys, and a key it names is changed. An update that says nothing about the review replaces the map as today, and carries `expires_at` and the ingest marks (`TestAnAcceptanceKeepsTheOtherSystemKeysAndItsDate`).
5. **`reviewed_at` is stable.** The same decision by the same reviewer, saved again without a date, keeps its date; so an identical re-ingest of an accepted document is `unchanged`. A new decision gets a new date (same test).
6. **Fail closed.** With the gate on, a brain whose gate query fails serves nothing: `allowDocument` answers false. Without the gate, expiry stays advisory, as #76 says (`TestTheGateFailsClosedWhenTheBrainCannotBeRead`, on a closed brain).
7. **An index** on the guarded `review_status` extraction, next to #76's on `expires_at`, in both backends; the gate query uses the predicate the planner answers from both (`TestTheReviewStatusIsIndexed` reads the plan). The PostgreSQL index is written with the same expression but not run here.

### Problem
On a shared brain, a fact a model extracted must not be served as truth before a person has looked at it. The brain had no way to say where a row stood, so the layer above had to keep that outside and hope nothing wrote straight in.

### Fix
Three metadata keys, on documents and memories alike: `review_status` (`proposed`, `accepted`, `rejected`), `reviewed_by` (required with a decision; the calling key when there is one) and `reviewed_at` (set to now on a new decision, kept on a re-save of the same one). They are checked on `ingest_document`, `knowledge_save`, `knowledge_update`, `memory_save` and `memory_update`, against the stored row: a request that says nothing about the review carries the decision over, and a decision is replaced by another decision, never erased.

**Hiding is opt-in**, as asked in #66. Keeping the status changes nothing by itself: every row is served, and a brain that never sets the field searches exactly as today. A brain opened with `cortexdb.WithReviewGate()` (`CORTEXDB_REVIEW_GATE=1` on `cortexdb-grpc` and `cortexdb-mcp-stdio`) leaves a proposed or rejected row out of every search and recall: documents through the same gate as expiry, memories at the five sites that already skip expired and superseded rows. Such a row stays reachable by id, by `memory_list_all` (`MemoryRecord` gains `ReviewStatus` and `ReviewedBy`), by its graph node, and for knowledge by the retrieval filter `review_status`, which works with or without the gate and is how a curator lists what waits.

`knowledge_save`'s document node now carries the record's metadata, `source_url` and `author` as properties, as `ingest_document`'s already did, so the review status is selectable in Cypher for both write paths.

## Performance Impact
Without the gate: one string check per write that sets a review key, nothing on read. With the gate: a map lookup per chunk, from the cache the expiry gate already loads, and one string compare per memory candidate.

## Breaking Changes
None. Three new optional metadata keys, two new fields on `MemoryRecord`, one new retrieval filter, one new option. Default behaviour is unchanged.
