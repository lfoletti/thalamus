## Description

### Problem
`ingest_document` keeps the caller's `metadata` on the chunks only. The document record and the document node carry none of it, and the tool has no `source_url` or `author` argument at all, while `knowledge_save` stores both. A search hit for a document ingested this way cannot say where it came from, so the two ingest paths answer the same provenance question differently.

### Fix
`ingest_document` takes `source_url` and `author`, and writes them with the caller's `metadata` on the document record and on the document node, the way `knowledge_save` does. The chunks keep the metadata they already had. A re-ingest replaces the record's provenance, as `knowledge_save` does. A call without the new arguments behaves as before, with the record and node now also carrying the metadata.

### Tests
- New `pkg/cortexdb/graphrag_ingest_metadata_test.go`: after `ingest_document` with `source_url`, `author` and `metadata`, the record, the document node and a search hit all report them; a re-ingest replaces them; the chunks still carry the metadata.
