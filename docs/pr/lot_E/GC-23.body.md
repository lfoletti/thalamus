## Description

`memory_get` reads one memory by `memory_id`, or several with `memory_ids`: the memories in the order asked, and the ids that name nothing, or a row outside the caller's scope, under `missing`. `knowledge_get` has the single form only. A client that has a list of document ids, for example the `group_by: [document_id]` of `aggregate_metadata` that the schema names for listing what waits for review, makes one `knowledge_get` call per document.

### Change
`knowledge_get` takes `knowledge_ids`, on the model of `memory_get`:
- The documents found come back under `knowledges`, in the order asked. `knowledge` is the first one found, as `memory` is for `memory_get`.
- An id that names no document goes to `missing`, the empty id included, instead of failing the call.
- Under a caller scope (`cortexdb.WithCallerScope`, set by both ports for a confined key), a document of a collection the caller may not read goes to `missing` too, at its place in the order asked, with nothing that tells it from an absent id. So does a document without chunks: the facade places it in the default collection, and the ports' row guard withholds it from every confined key (`authz.Scope.guardRow`), so the list does as the single form does at the port.
- A document that cannot be read is an error, as in the single form, never `missing`.
- The list form serves what the single form serves by id: an expired document, and a proposed one under the review gate (`ReviewGateNote`: "knowledge_get and memory_get still read a hidden row by id").
- With both forms, the list is read, as in `memory_get`.
- The single form does not change. It stays unscoped in the facade, as `GetMemory`'s does: the row guard of the ports reads through it.
- The schema drops `knowledge_id` from `required`, as `memory_get`'s schema has none.

The allowlist takes `knowledge_ids` as data on `knowledge_get`, as `memory_ids` on `memory_get`, and a confined key sends one form at a time (`oneOf`). With both, the guard would read `knowledge_id` and the facade the list, so a foreign id beside a list of the caller's own would tell a foreign row from a missing one.

## Performance Impact
None for the single form. The list form loads each document as the single form does (record, chunks, entity names), one after the other.

## Breaking Changes
None. A call with `knowledge_id` alone is answered as on `main`. The response gains two optional fields, `knowledges` and `missing`.
