## Description

`knowledge_save` and `knowledge_update` sign the document they write: under a writer (`cortexdb.WithWriter`, set by both ports from the calling key), `written_by` is the key and a client cannot claim another. `ingest_document` did not sign. A document it wrote kept the `written_by` the client sent, or had none. The comment on `writerKeys` in `pkg/authz/allowlist.go` says so ("but not on ingest_document"), and so does `TestAToolWriteTakesTheMarksTheFacadeReplaces` ("carries them and no signature").

Two effects on `main`:
- A key with no collection scope can sign a document as any other key through `ingest_document`. The allowlist refuses `metadata.written_by` to a confined key only.
- A confined key that reads a document written by `knowledge_save` gets `written_by` back. Sent back through `/v1/tools/knowledge_save`, `/v1/tools/knowledge_update` or `/v1/tools/ingest_document`, the metadata is refused with 403 ("takes no metadata.written_by from a confined key"). The typed routes strip the two keys before the allowlist, because the facade signs them (`knowledgeToolArgs` in `pkg/httpapi/policy.go`, `authorizeTypedArgs` in `pkg/rpcserver/ownership.go`). The tool route did not, because one of its three document tools did not sign.

### Fix
- `IngestDocument` calls `stampWriter`, as `SaveKnowledge` does: with a writer in the context, `written_by` is the writer and `updated_by` is removed. Without one (an embedded library, a server without keys), the metadata is stored as given. `author` is not touched: it stays the client's data, as on `knowledge_save`.
- The signature is set before the "unchanged" comparison. The same text by the same key is still unchanged. The same text by another key is written again and signed by that key, as `knowledge_save` re-signs every save.
- `cortexdb.WriterKeys()` names the two keys. The allowlist's `rewritten` keys of `ingest_document`, `knowledge_save` and `knowledge_update` are now `EngineDocumentKeys` plus `WriterKeys` (`documentKeys`). So these three tools take `written_by` and `updated_by` back under their exact spelling, as the typed routes do. Another spelling (`Written_By`) is not replaced by the facade and stays refused.
- `InsertGraphDocument` is authorized against the `ingest_document` line, and it does not sign. Without a change it would have taken the signature back too. `authorizeTypedArgs` now refuses `written_by` and `updated_by` on it, with the message the allowlist gave on `main`.

### Tool by tool, confined key

| `knowledge_update` (tool route) | 403 | taken | `written_by` kept, `updated_by` = key (as on `main`) |

Unconfined key, `ingest_document` with `written_by`: `main` keeps the client's value; this PR stores the key.

### Scope
- The memory tools sign too (`SaveMemory`, `UpdateMemory`), and the tool route still refuses the signature on them. That is the same round trip for memories; I left it out to keep one rule here. See Questions.
- `InsertGraphDocument` still does not sign. Signing it would make every document write sign; it is a separate change.

## Performance Impact
None. One map write and one map delete per ingest when a writer is set.

## Breaking Changes
- `ingest_document` under a key now stores `written_by` = the key, and drops a sent `updated_by`, whatever the client sent. A library caller without `WithWriter` sees no change.
- A sync job that re-ingests documents stored before this change, under a key, rewrites each of them once: the stored row has no `written_by`, so the first ingest is not "unchanged". After that it is.
- A confined key may now send `written_by` and `updated_by` back to the three document tools; they are replaced, not refused.
