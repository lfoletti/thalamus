## Description

`extract_conversation` with a `session_id` and no `text` reads the session's messages (`loadSessionText`, `pkg/cortexdb/extract_conversation.go`) without asking the caller scope. Under a `CallerScope` that does not permit the session's bucket, it still summarized the session: its first sentences, themes, entities and co-occurrences, and with `persist: true` it wrote the summary as a document and the entities into the graph. The typed memory reads (`GetMemory`, the searches in `memory_api.go`) check `memoryReadPermitted` for the same bucket and hide it.

No server exposes this today. The allowlist refuses `session_id` and `persist` for `extract_conversation` from a confined key (`pkg/authz/allowlist.go`), and an unconfined key has no `CallerScope`. The caller who reaches it is a program that embeds `pkg/cortexdb`, sets `WithCallerScope` itself and calls `ExtractConversation` or `GraphRAGToolbox.Call`. `CallerScope` says its checks are "on what a request resolves to, not on its fields"; this PR makes `extract_conversation` hold that contract.

The allowlist keeps its refusal. A collection-confined key's `CallerScope.Memory` permits no bucket, so opening `session_id` to it would only return "missing" sessions; a user-confined key does not get the tool. This PR does not change that.

Independent of the other open PRs: based on `main`, touches `pkg/cortexdb/extract_conversation.go` only: 10 lines outside tests, none removed.

### Fix
`loadSessionText` first asks `memoryReadPermitted` for the session id:
- not permitted: it loads nothing, so `extract_conversation` answers exactly as for a session that does not exist (`extract_conversation: text or session_id is required`). The answer does not tell that the session exists. Nothing is persisted.
- a bucket that cannot be read: an error (`extract_conversation: load session: …`), never a pass.
- without a `CallerScope`, or with one that permits the bucket: unchanged. `memoryReadPermitted` returns at once when no scope is set.

## Performance Impact
One `GetSession` per `extract_conversation` that reads a session, and only when a `CallerScope` is set. Nothing otherwise.

## Breaking Changes
None. A caller with a `CallerScope` that does not permit a session can no longer extract it; without a scope nothing changes.
