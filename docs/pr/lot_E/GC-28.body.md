## Description

A synthesis written by a model cites its sources sentence by sentence, and a reader wants to know, before keeping it, whether each sentence says something its sources do not. `verify_claims` checks (subject, relation, object) triples against graph edges and never reads text; `uncited_facts` lists edges with no provenance. Neither compares a sentence with the text it cites. This PR adds a read-only tool for that, `check_against_sources`.

Independent of the other open PRs: based on `main`, adds `pkg/cortexdb/check_sources.go`, the tool definition, its `Call` case and MCP registration, and one allowlist line.

### The tool
```json
{"collection": "ai-music",
 "sentences": [{"text": "Google DeepMind released Lyria RealTime in 2025.", "sources": ["doc-id", "chunk:doc-id:003"]}],
 "equivalents": {"rgpd": ["gdpr", "dsgvo"]}}
```
For each sentence, in the order of the request: `missing`, the facts of the sentence that no cited source contains; `sources_missing`, the sources that could not be read; `holds`, true when the sentence cites a source, every source was read and nothing is missing (`TestCheckAgainstSourcesReadsDocumentsAndChunks`, `TestAMissingSourceIsNamedAndTheSentenceDoesNotHold`, `TestASentenceWithNoSourceDoesNotHold`). `counts` gives the sentences checked and those that held. Deterministic, no model. It says what the sources do not say, not whether the sentence is true.

### The rules
A pure core (`sentenceFacts`, `missingFacts`, `factPresent`, `foldFact`) takes a sentence, the texts and the equivalents, and returns the missing facts. It is tested without a database.
- A fact is a number, or a word with a digit, a capital after its first letter, or an initial capital and four letters or more (`TestAFactIsANumberOrAMarkedWord`). A decimal comma reads as a point.
- The first word is no fact when only its initial is a capital; an acronym in first place stays one (`TestTheFirstWordIsNotAFactWhenOnlyItsInitialIsCapital`).
- A token of digits alone is the number, not a word as well: `1,5` gives `1.5`, not also `1` and `5` (`TestADigitOnlyTokenIsANumberNotAWord`).
- Case and accents are folded on the sentence, the sources and the equivalents alike, `ß` as `ss` (`TestFoldingIgnoresCaseAndAccentsOnBothSides`).
- A number is found only between two non-digits: `7` is not in "17 layers", `2025` is in "in 2025,". A word is found inside a longer one (`TestANumberIsFoundOnlyBetweenNonDigits`).
- The engine holds no word list. What a fact may be written as in another language comes from the request (`TestAnEquivalentFromTheRequestStandsForTheFact`); without it, RGPD is not GDPR, and a capitalised word after a full stop inside the sentence is a fact (`TestTheEngineHoldsNoWordList`).
- A run of Han, kana or hangul is cut from the Latin and digits beside it, and is never a fact: what stays checkable in those scripts is the numbers and the Latin names (`TestHanKanaAndHangulRunsAreNoFactAndAreSplitFromLatin`).
- The sentence is read in NFKC first, so full-width digits and letters are the ASCII ones (`TestFullwidthDigitsAreNumbers`).

### The sources
One function reads the texts, `sourceTexts`. A chunk id is read through `loadToolChunks`, which already leaves out a chunk of an expired or hidden document; its collection is the chunk's own. Any other id is read as a document, held to `hiddenAmong`, and its collection is `knowledgeCollection`'s. A source is missing when it does not exist, when it is expired or hidden by the review gate (`TestAnExpiredOrProposedSourceIsMissing`), when `collection` is set and the source is in another one (`TestASourceOfAnotherCollectionIsMissing`), or when the caller's scope does not permit its collection, even with no `collection` in the request (`TestACallerScopeOutsideTheCollectionSeesNoSource`). A source that cannot be read is an error, never a missing source (`TestACheckWhoseSourcesCannotBeReadFails`). At most 500 sentences per call and 50 sources per sentence (`TestTheCheckIsBounded`).

`golang.org/x/text` moves from an indirect to a direct dependency, at the version already in `go.mod` (v0.36.0), for NFKC and NFKD.

## Performance Impact
None outside the tool. Per call: one `embeddingsByIDs` and one `hiddenAmong` for all the sources together, then one `GetByID` per chunk source and one `GetDocument` plus `knowledgeCollection` per document source, and a scan of the joined source text per fact. The bounds keep a call to 500 sentences and 50 sources each.

## Breaking Changes
None. A new tool; the toolbox has 101 tools.

## Questions
1. **The grade of a synthesis.** A synthesis written by a model and checked by this tool: is it `self_consistent`, or `asserted` with the result in its `_state` (for instance `checked: 41/43`)? The derivation is not deterministic, so I would say `asserted`. The tool sets no grade either way.
2. **CJK scripts.** Runs of Han, kana and hangul are never facts here, so a check in those scripts covers numbers and Latin names only. Do you want runs of N characters or more as facts? That needs a segmentation the engine does not have.
3. **Suffixes or equivalents.** Plurals and ordinals (`models`, `20th`) are language rules, so they stay out of the engine; a fact written another way needs an equivalent. Would you rather have a neutral `suffixes` field in the request, or keep `equivalents` alone?
4. **The word boundary.** A word is found inside a longer one, which tolerates inflection but also finds `AI` in "said". Numbers already need non-digits around them. Should words need a word boundary too?
5. **Proposed sources when the review gate is off.** Without `CORTEXDB_REVIEW_GATE`, a proposed document counts as a source, as it does for every other read. Should a check leave proposed sources out always?
6. **The limits.** 500 sentences per call and 50 sources per sentence, refused above. Are these the values you want, and should the source text read per call be bounded as well?
