## Description

Two lexical paths stop after the question when it alone fills `top_k`, so the alternate queries (and the keyword queries) never run:
- `searchTextCandidates` (`graphrag_tool_search.go`), behind `search_text` and `SearchKnowledge`;
- `searchTextOnlyExpanded` (`text_search.go`), behind `SearchTextOnly` with `Keywords` or `AlternateQueries`, which `cortex_query`'s lexical prefetch uses.

A row that only a variant finds can then never be in the result, whatever its score. Measured: six French rows hold every word of "conseil procédure cantons", one German row answers only the variant "Bundesrat Verfahren Kantone"; with `top_k` 3 or 5 the result is the French rows only.

### Fix
The two `break`s go. Every phrasing runs, and the existing merge decides. The memory path has no such exit and is unchanged.

### What the merge then does
The rule here is that the variants run. How the merge ranks what they find is unchanged, and it matters:
- `SearchTextOnly` (expanded) merges each query's own score; in the test the short German row ranks first.
- The tool path merges the score each phrasing's `SearchTextOnly` returns, which is rank-based (1/61 for a first row), scaled by the phrasing's position (0.95 for the first variant). A variant's best row then comes after the question's first four rows: 0.95/61 < 1/64. Measured on the scenario above, through `SearchKnowledge` and `search_text`: with `top_k` 3 the German row is still out; with `top_k` 5 it is fifth; with `top_k` 10 it was already fifth on `main` (the question had only six rows).

So with this PR a variant reaches a result of five or more. A rank fusion across phrasings (reciprocal rank, without the position penalty) would let it reach the first places. That is another rule, so a later PR, measured first on the Swiss set of #gc-24. I have not added it here.

### Tests
`pkg/cortexdb/lexical_variants_run_test.go` (SQLite):
- `TestSearchTextRunsAlternatesWhenQuestionFillsTopK`: the tool path, `top_k` 5, the German row is among the five.
- `TestSearchTextOnlyRunsAlternatesWhenQuestionFillsTopK`: `SearchTextOnly` with `AlternateQueries`, `top_k` 3, the German row is among the three.

## Performance Impact
When the question fills `top_k`, the remaining phrasings now run: one full-text query each (the alternate queries, then two keyword OR queries). Before, such a search ran one query.

## Breaking Changes
None. Searches whose question fills `top_k` can now return rows that only a variant or a keyword finds.
