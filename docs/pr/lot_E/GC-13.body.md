## Description

`find_nodes` resolves names to graph nodes by reading the content of every node, the text of chunks included. Its matches did not pass the filter that `get_nodes` and the walks apply since v2.137.0 (`withoutExpiredDocuments`). So `find_nodes` served the chunk and document nodes of an expired document, with their text, and under the review gate (`CORTEXDB_REVIEW_GATE=1`) those of a proposed or rejected document and the nodes of a proposed or rejected memory. `get_nodes` on the same node ids leaves them out.

Independent of the other open PRs: based on `main`, one file of `pkg/cortexdb`: 22 lines outside tests, 9 removed.

### Fix
`FindNodes` passes its matches through `withoutExpiredDocuments`, as `GetNodes` does (`pkg/cortexdb/graphrag_tool_find_nodes.go`):
- A chunk or document node of a hidden document, and a memory node the review gate hides, is not a match.
- Hidden matches do not use up the limit. The ranked matches are loaded a window of `limit` at a time, filtered, and kept until the limit is full.
- `match` (exact, fold, contains) is the strength of the first node served, not of a hidden node ranked above it. A name whose matches are all hidden gets no node and no `match`, as a name nothing matches.
- Entity nodes are served as before: an entity that only a hidden chunk mentions is still found, as `get_nodes` still serves it.

### Scope
- The filter is the one of #76 and #77. A store that cannot be read under the review gate hides the node, as it does for `get_nodes`.
- Before, the ranked matches were cut to `limit` and then loaded. Now a window is loaded, and the next one only when hidden nodes left room.

### Tests
`pkg/cortexdb/graphrag_tool_find_nodes_hidden_test.go`:
- `TestFindNodesLeavesOutTheNodesOfAnExpiredDocument`: neither the text, the chunk node nor the document node of the expired document; the live document's chunk stays.
- `TestFindNodesLeavesOutAProposedDocumentUnderTheReviewGate`: a proposed document and a proposed memory are left out; the unreviewed ones stay.
- `TestFindNodesStillFindsAnEntityThatAHiddenChunkMentions`: the entity alone, `exact`.
- `TestFindNodesFillsItsLimitPastHiddenMatches`: with two hidden matches ranked first, limits 1, 2 and 3 return the first one, two and three live chunks, `contains`; the strength is that of the first node served (`exact`, not `contains`); a name whose matches are all hidden gets nothing.

`pkg/cortexdb/expiry_class_test.go`: `find_nodes` moves from "entities and relations" to "gated" in `readToolsAndTheExpiry`, so the class tests of #76 and #77 call it: `TestEveryReadToolIsGatedOrNamed` (expired document) and `TestEveryGatedReadToolHidesAProposedDocument` (review gate).

**Failing first.** On `main`, the six tests above fail, for example `find_nodes served the expired document (EXPIREDTEXT)`, `find_nodes limit 1 = [chunk:old1:000] (exact), want the live chunk, contains`, and `find_nodes returned the expired document (harbour)` in both class tests. Every rule then has a hand mutation that a named test catches, six in all, six killed: the filter not called, only the first window read, the strength taken from the first ranked match, the limit not applied to the window, the strength taken from the last node served, the ranking order lost. Replay: `go test ./pkg/cortexdb/ -run 'TestFindNodes|TestEveryReadToolIsGatedOrNamed|TestEveryGatedReadToolHidesAProposedDocument'`. Every line of the patch has a test.

## Performance Impact
One query on `documents` per window of matches (`hiddenAmong`), and one memory read per memory node under the review gate, as for `get_nodes`. When hidden nodes fill a window, the next window is loaded. Nothing changes for a name with no match.

## Breaking Changes
None. `find_nodes` no longer serves the nodes of an expired document, or under the review gate those of a proposed or rejected document or memory, which `get_nodes` already left out.
