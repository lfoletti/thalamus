## Description

The allowlist of #72 refuses `cortex_query` to a confined key, with the reason "its graph prefetch searches chunks of every collection". Since #78 (v2.135.0) the graph lane keeps only the chunks of the collection queried (`runGraphQueryPrefetch`, `chunksInScope`), and the vector, lexical and hybrid lanes pass the collection to the store. `POST /v1/query`, which runs the same `db.Query`, already serves a key confined to a collection that names it. The tool route and `CallTool` still refused the tool.

Independent of the other open PRs: based on `main`, one file of `pkg/authz` (30 lines outside tests, 1 removed), tests in `pkg/authz`, `pkg/rpcserver` and `pkg/httpapi`.

### Fix
`cortex_query` moves from `refusedTools` to `confinedTools` (`pkg/authz/allowlist.go`):
- `collection` is its scope field. A confined key must send it, equal to its own collection, under every spelling, as for `knowledge_search`.
- It touches knowledge only, so a key confined to a user is refused it (`takes no user_id argument`).
- Every other argument the schema declares is classified as data: the lanes (`prefetch[].name`, `kind`, `query`, `query_vector`, `entity_names`, `weight`, `limit`, `keywords`, `alternate_queries`), `query`, `query_vector`, `entity_names`, `fusion`, `filter` and its conditions, `formula` and its boosts, `limit`, `rrf_k`, `include_raw`. A filter or a formula only narrows or reorders what the lanes found in the collection.
- `prefetch[].max_hops` is refused, with its reason: past the mention edge, the graph lane walks relations that other collections state, so a chunk of the collection reached two hops away tells the caller that such a relation exists. The lane keeps its default depth of one hop.
- The source lane (`kind: "source"`) needs `prefetch[].source`, which the schema does not declare, so the allowlist refuses it as any argument it does not classify.

### Scope
- `max_hops` waits for #<GC-17>. That PR makes the graph lane of a query with a collection walk only what the collection may see, on every port, `POST /v1/query` included. Once it is merged, a later change can move `prefetch[].max_hops` from `denied` to the data of this line.
- The two review tests that held the refusal (`TestTheWaysOutOfAConfinementFoundInReviewAreClosedOverGRPC` and `…OverREST`, point 3) now hold the confinement instead: the key's query returns its note and not the other collection's text, and `max_hops` is refused.

### Tests
`pkg/authz/allowlist_cortex_query_test.go`:
- `TestAConfinedKeyQueriesItsCollectionOnly`: a call with every argument of the schema but `max_hops`, on the key's collection, passes; no collection, another collection, and a second spelling naming another collection are refused; a key confined to a user is refused the tool.
- `TestAConfinedKeyMayNotSendMaxHopsToTheGraphLane`: `max_hops` in a lane, and `MAX_HOPS` in a second lane, are refused with the reason; the graph lane without it passes.
- `TestAConfinedKeyMayNotNameAQuerySource`: `prefetch[].source` is refused.

`pkg/rpcserver/confined_cortex_query_test.go`, `TestAConfinedKeyQueriesItsCollectionOnlyOverGRPC`, and `pkg/httpapi/confined_cortex_query_test.go`, `TestAConfinedKeyQueriesItsCollectionOnlyOverHTTP`: two documents mention one entity, one in `notes`, one in `secrets`. The `notes` key gets the `notes` chunk and not the other, on the default lanes, the lexical and graph lanes, and over gRPC the vector and hybrid lanes too. The operator's key, with no collection, gets both, so the check can fail. Another collection, no collection, `max_hops` and a source are `PERMISSION_DENIED` and `403`, each with its reason.

`TestEveryToolAndEveryArgumentIsClassifiedForConfinedKeys` holds the new line to the schema, both ways.

**Failing first.** On `main`, the five new tests fail with `cortex_query is not a tool a confined key may call` on each port, and so do the two review tests as amended and the completeness test (`cortex_query has a reason of its own the test does not name`). Every rule then has a hand mutation that a named test catches, six in all, six killed: the tool off the allowlist, no scope field, `max_hops` classified as data, an argument of the filter left unclassified, the tool still on `refusedTools`, `prefetch[].source` classified as data. Replay: `go test ./pkg/authz/ ./pkg/rpcserver/ ./pkg/httpapi/ -run 'CortexQuery|QueriesItsCollection|MaxHops|QuerySource|Classified|OffTheAllowlist|Review'`. Every line of the patch has a test.
