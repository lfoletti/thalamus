## Description

An alternate query runs as an AND of all its words (`sanitizeFTSQuery` quotes each word), and its words never reach the OR keyword query: that query takes the question's words and the `keywords` only (`lexicalSearchQueries`, `graphrag_tool_helpers.go`). A variant written as a sentence rarely has all its words in one row, so it finds nothing. Measured: with the French question "Qui règle la procédure des cantons ?" and the variant "Wie regelt der Bund das Verfahren der Kantone?", the German row "Der Bundesrat regelt das Verfahren der Kantone im Einzelnen." is not found by `SearchKnowledge`, `search_text` or `SearchMemory`. The same variant written as keywords ("Bundesrat Verfahren Kantone") finds it.

`keywords` do not have this defect: their words already join the OR query.

### Fix
The words of the alternate queries join the OR keyword query (and its prefix form), as those of `keywords` do. They go through the same `lexicalQueryKeywords` (lowercase, stopwords out). The question's own OR query is unchanged. Each alternate query still runs as before too. This touches the knowledge, tool and memory paths, which share `lexicalSearchQueries`.

The coverage floor already counts alternate-query words as synonyms at half weight (`newRarityQuery`), so a row found only through a variant's function words ("der", "das") is still refused. `TestKnowledgeSearchFindsDocumentThroughAlternateSentence` and the memory test check it with such a row.

### Tests
`pkg/cortexdb/lexical_variant_words_test.go` (SQLite):
- `TestLexicalSearchQueriesTakeAlternateWords`: the OR query holds the variant's words, and the question's own OR query is still there.
- `TestKnowledgeSearchFindsDocumentThroughAlternateSentence`: the German answer comes first; a German row that shares only the variant's function words is not returned.
- `TestSearchTextFindsDocumentThroughAlternateSentence`: the tool path.
- `TestMemorySearchFindsMemoryThroughAlternateSentence`: the memory path, with the same refusal.

## Performance Impact
The OR keyword query has more terms when alternate queries are given: one more term per distinct content word of the variants. No extra query is run.

## Breaking Changes
None. Searches with alternate queries can return rows that only a variant's words reach.
