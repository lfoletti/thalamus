1. **The expiry is the explicit field, and nothing else.** `expires_at` on `ingest_document`, `knowledge_save` and `knowledge_update` is the only way to set it; the engine keeps it under its own key, `_expires_at`, with the leading underscore importflow uses for `_table`. A metadata key named `expires_at` is the caller's: stored as it came, never validated, never read as an expiry, so an imported DATETIME column neither fails the import nor hides the row (`TestAClientKeyNamedExpiresAtIsStoredAsIsAndNeverRead`), and a row written by `main` with such a key is updated like any other, by title or otherwise (`TestARowWrittenByMainWithThatKeyIsStillUpdatable`). A caller's copy of `_expires_at` in metadata is dropped (`TestTheEngineKeyInClientMetadataIsDropped`). On all three tools the field is a pointer: absent, the stored expiry is kept whatever the write does with metadata, so a sync job that re-ingests from the source does not lift a retention rule; empty, it is removed (`TestTheExpiryIsSetAndRemovedByTheExplicitFieldOnly`, `TestAnExpiryCanBeSetOnARecordWithoutMetadata`). `InsertGraphDocument`, the fourth write of a record, has no field and keeps the stored expiry too (`TestInsertGraphDocumentKeepsTheStoredExpiry`). An instant whose year leaves 0001 to 9999 once in UTC is refused, since the gate compares the stored text (`TestAnExpiryOutsideFourDigitYearsIsRefused`). The expiry lives on the record alone: it is not copied onto the chunks or the document node, where an expiry-only `knowledge_update` would leave a stale copy (`TestTheExpiryIsKeptOnTheRecordOnly`).

- On a read failure the expiry gate is advisory, because the sweep is the guarantee; the review gate of #77 fails closed, because hiding is its whole point.

### Problem
A memory carries `ttl_seconds` and every memory read skips the expired ones, but nothing ever removed them, and a document had no expiry at all. A retention rule, "this source is kept five years, then it goes", had to be enforced by hand with a list of ids.

### Fix
- `ingest_document`, `knowledge_save` and `knowledge_update` take `expires_at` (RFC 3339); a bad value or a year outside 0001 to 9999 in UTC is refused, a zoned one is stored as UTC, under the engine's key `_expires_at`.
- A document past its expiry is left out of every search, recall and chunk read: the lexical, vector, hybrid, graph and PPR lanes of `knowledge_search` and `cortex_query`, the chunk tools, `get_nodes`, `expand_graph`, `search_vector_range`, `knowledge_memory_neighbors`, `aggregate_metadata`, `representative_records`, the exported searches of the library and the typed search RPCs. One SQL predicate, on the expression the index is built on, serves the gate, the dedupe lookup, the aggregates and the sweep. The gate is advisory on a read failure; the sweep is the guarantee.
- `DB.SweepExpired`, the tool `sweep_expired` and `cortexdb-mcp-stdio --sweep-expired [--dry-run] [--json]` remove the expired documents (record, chunks, graph nodes) and the expired memories, each document in one transaction that checks the expiry again. On a client of a shared brain the command sweeps that brain through the tool.

A document with no expiry is served and kept exactly as before.

## Performance Impact
One indexed query per read call, over the document ids the call met (an `IN` list), and one subquery inside the aggregate's own statement; no cache. `expand_graph`, `search_paths` and `knowledge_memory_shortest_path` make two more when the edges they return carry provenance (the chunk nodes the edges name, then their documents), once per call, not once per path. A search whose hits are mostly hidden asks the store again with four times the budget, at most until the store runs out of rows; with no expired document it asks once, as before. 130 µs per call on 10 000 documents with 50 hits, against 4 µs with the cache of the first version warm. Nothing for a write.

## Breaking Changes
None. One new tool, `sweep_expired`; one new field on three requests; one new metadata key, `_expires_at`. The key of the first version, `expires_at`, was never released. `ExcludeDocuments` on the two aggregate requests is new and not part of their JSON.
