### Problem
On a shared brain, a fact a model extracted must not be served as truth before a person has looked at it. The brain had no way to say where a row stood, so the layer above had to keep that outside and hope nothing wrote straight in.

### Fix
Three fields on the five write tools: `review_status` (`proposed`, `accepted`, `rejected`), `reviewed_by` (required with a decision; the calling key when there is one) and `reviewed_at` (given, or now, or the stored instant when the same reviewer repeats the same decision). The decision is kept under the engine's keys `_review_status`, `_reviewed_by`, `_reviewed_at`, on the record only: the document node and the chunks carry no copy, so a decision by `knowledge_update` counts at once, and a curator lists by a filter on `_review_status`, not by a `group_by` on it. `knowledge_memory_remember` takes the request of `memory_save`, so it decides too; its schema lists no review field, and a confined key cannot send one. A write that says nothing about the review carries the decision over; a decision is replaced by another decision, never erased.

**Hiding is opt-in**, as asked in #66. Keeping the status changes nothing by itself: every row is served, and a brain that never sets the fields searches exactly as today. A brain opened with `cortexdb.WithReviewGate()` (`CORTEXDB_REVIEW_GATE=1` on `cortexdb-grpc` and `cortexdb-mcp-stdio`) leaves a proposed or rejected row out of every search and recall: documents through the same one-query gate as the expiry, memories at the five sites that already skip expired and superseded rows and in the graph walks from a node. A hidden memory is not promoted to knowledge, nor put in a conversation summary. Such a row stays reachable by id, by `memory_list_all`, by `plan.filters.review_status` on `knowledge_search`, and by a filter on `_review_status` on `aggregate_metadata` and `representative_records`.

## Performance Impact
Without the gate: one string check per write that decides, nothing on read. With the gate: the one indexed query per call #76 already makes, with one more term on the status, one string compare per memory candidate, and one primary-key read per memory node a graph walk meets.

## Breaking Changes
None. Three new optional fields on five tools, two new fields on `MemoryRecord`, one new retrieval filter, one new option. Default behaviour is unchanged. The metadata keys of the first version (`review_status`, `reviewed_by`, `reviewed_at`) were never released; a caller that set them gets them back as its own metadata.
