## 2 bis. Écarts au plan, lot C (21 octobre 2026)

- **#75, PostgreSQL** : la CI amont ne démarre pas PostgreSQL, donc les 3 lignes du verrou consultatif (`knowledge_tx.go`, `contentHolderTx`) resteront non couvertes chez Codecov : à déclarer dans `## Codecov` du corps (« exercised locally against PostgreSQL 17 by TestTheIngestPathsHoldOnPostgres and TestADedupeIngestThatCannotLockTheHashIsReported »). Le chemin d'erreur du verrou est provoqué par `lock_timeout=200ms` sur la chaîne de connexion du cerveau et un verrou tenu par une autre session. `make pgtest` inclut désormais `./pkg/cortexdb/`.
- **#75, mutation « dédup hors transaction »** : sur SQLite, la file d'attente d'écriture sérialise toute transaction, même une transaction de lecture ouverte avant celle d'écriture ; une lecture déplacée hors de la transaction ne change le comportement que dans une fenêtre de quelques microsecondes, qu'aucun test ne peut tenir. La mutation est remplacée par le retrait du verrou PostgreSQL, qui tombe 6 fois sur 6 sur les deux tests PostgreSQL. La règle « lecture dans la transaction d'écriture » est donc prouvée sur PostgreSQL ; sur SQLite elle est garantie par la file d'attente du magasin.
- **#76, D2 précisée** : `expires_at` est une chaîne sur `ingest_document` et `knowledge_save` (qui remplacent l'enregistrement : absent et vide signifient tous deux « pas d'expiration ») et un pointeur sur `knowledge_update` seulement (absent = reporté, vide = retiré). Un pointeur sur un outil de remplacement n'aurait aucun sens observable.
- **#76, D1 c précisée** : le moteur retire de `metadata` les clés qu'il possède lui-même (`_expires_at` ici, `_review_*` dans #77), pas toute clé à préfixe `_` : une clé `_foo` d'un client est inoffensive (jamais lue) et la règle exacte ferme la classe sans liste des clés de l'amont.
- **#76, porte** : plus de cache. `hiddenDocuments(ctx, now, among)` fait une requête par appel sur les identifiants rencontrés (`IN`), ou sur toute la table pour les agrégats et le balayage ; un seul prédicat SQL (`expiredPredicate`) sert la recherche, le balayage et les agrégats, et sa négation explicite (`visiblePredicate`, parce que `NOT NULL` n'est pas vrai) sert la dédup. `aggregate_metadata` et `representative_records` passent par `ExcludeDocIDs` sur les deux requêtes de `pkg/core` (les deux magasins, `doc_id IS NULL` gardé).
