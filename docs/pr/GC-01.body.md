## Description

### Problem
The gRPC request log says which method ran and how it ended, but not which key made the call, nor which tool a `CallTool` ran. On a server shared by several keys a trace cannot answer "which key wrote this document" or "which key is being refused, and on what". `CORTEXDB_TRACE_FILE` records have the same gap.

### Fix
The auth interceptor tags the context with the authenticated key's `id` (never its secret). The request log prints `key=<id>` on every served and denied call, and `tool=<name>` on a `CallTool`, read from the request before dispatch so a denied call is named too. `CORTEXDB_TRACE_FILE` records carry the same two fields. With no key file the fields are absent, so an unauthenticated server logs exactly what it did before.

### Tests
- New tests in `pkg/rpcserver/trace_test.go`: a served call, a denied call and a `CallTool` each log the key and, for the tool call, the tool name; without a key file the log line is unchanged.
- `go vet` and `go test -race ./...` pass.
