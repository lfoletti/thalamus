# Thalamus

Couche mince au-dessus de CortexDB pour des graphes de connaissances d'entreprise utilisés par des agents de code. Contenu : les documents du projet, un clone de CortexDB avec sept PR ouvertes en amont, et depuis le 20 octobre 2026 la première tranche du gateway (`gateway/`). La racine est un dépôt git (initialisé le 20 octobre 2026, branche `main`), poussé le même jour sur GitHub (**privé**, MIT, remote `origin`). Nom du projet depuis le 20 octobre 2026 au soir : **Thalamus** (décision de Lauro ; le thalamus relaie et filtre tout ce qui monte au cortex), préfixe d'outils `th_`, binaires `th-gateway` et `th-hook`, module `github.com/lfoletti/thalamus/gateway`, plugin `thalamus`, clés `th/<login>/<cerveau>`. Dépôt GitHub renommé `lfoletti/thalamus` le 20 octobre 2026 au soir (GitHub redirige l'ancien nom), `origin` mis à jour. Le dossier sur disque reste `granular_cortex` ; `cortexdb/` est un dépôt à part, ignoré par la racine. Passage en public prévu à la fusion des sept PR amont, avec le commentaire de clôture de #66. Aucun push sans demande explicite de Lauro, même vers ce dépôt.

## Arborescence

- `docs/` : documents du projet.
- `gateway/` : module Go `github.com/lfoletti/thalamus/gateway` (CortexDB v2.138.0 en bibliothèque depuis le 23 octobre 2026, SDK MCP v1.6.1). Paquets `rights` (lecture de `rights.yaml`), `identity` (vérification d'un `id_token` OIDC, sans bibliothèque), `keys` (émission et révocation des clés confinées dans le fichier de clés du serveur), `relay` (serveur MCP HTTP par cerveau, relais gRPC avec la clé de l'appelant, `audit.jsonl`), `login` (côté employé de `/v1/login` : code + PKCE, boucle locale), `cmd/th-gateway`, `cmd/th-hook`. Lire `gateway/README.md`.
- `plugin/` : plugin Claude Code `thalamus` (hook de rappel, serveur MCP du gateway, compétence). Lire `plugin/README.md`.
- `extension/` : extension Chrome (Manifest V3, sans bibliothèque) qui propose la page ou la sélection par `POST /v1/add`. Règles dans `lib.js` (tests `node --test`, mutations dans `gateway/mutate.py` sous le paquet `extension`), pilote Playwright `e2e_driver.mjs`, `node_modules/` ignoré (`npm install` une fois, Playwright 1.58.2 = Chromium 1208 en cache). Lire `extension/README.md`.
- `tests/e2e_gateway.sh` : banc de bout en bout du gateway (serveur gRPC construit depuis `cortexdb/`, 69 contrôles, environ 1 min). `tests/e2e_plugin.sh [modèle]` : session Claude Code réelle avec le plugin (11 contrôles dont un cerveau local, la pyramide et `th_descend`, trois appels au modèle ; 11/11 avec haiku le 22 octobre 2026 après la tranche 16). `tests/e2e_extension.sh` : l'extension Chrome dans Chromium devant un vrai gateway et le faux fournisseur (13 contrôles dont la connexion et l'extraction du contenu principal, environ 30 s). `tests/e2e_shared_brain.sh` : le banc du clone seul (30 contrôles).
- `cortexdb/` : clone complet de `github.com/liliang-cn/cortexdb` (amont, `origin` ; fork de l'utilisateur, `fork` = `lfoletti/cortexdb`). Branche de travail : `proto/granular-cortex`, créée le 18 octobre 2026, reconstruite le 22 octobre 2026 sur v2.136.0 (`0328e0a`) : les têtes du lot C (#75 `f4c5aa7`, #76 `73ed740`, #77 `4fefb91`) et un commit de changelog `455ad45` (entrées `Unreleased` des trois PR). ## Règles de publication

- Tous les correctifs se développent **localement** sur `proto/granular-cortex`, **un commit par correctif**, avec une entrée `Unreleased` dans `CHANGELOG.md`. Cette entrée est à usage interne : le propriétaire amont écrit seul le changelog à la release, donc chaque PR retire cette modification (`docs/plan_publication.md`, section 0 bis).
- Le produit final se teste en entier avant toute soumission.
- **Tests « failing first »** (exigence du propriétaire amont, règle générale depuis le 19 octobre 2026) : chaque test d'une PR doit échouer sans son code. Vérifier avant toute PR : fichiers de test posés sur l'arbre sans le correctif, ou mutation de chaque règle si les tests ne compilent pas sans elle. Preuve dans le corps de la PR, section « Failing first ». Méthode et exemple : `docs/pr/lot_B/failing_first.md`.
- **Aucun push, aucune pull request** vers l'amont ou le fork sans demande explicite de l'utilisateur. La soumission se fera par petits lots, après validation d'un plan de publication.
- **PR en brouillon d'abord** : une PR s'ouvre en brouillon et ne passe à la relecture qu'après un rapport Codecov à zéro ligne non couverte sur sa tête (ou les seules lignes de `main` déclarées). Voir le pipeline ci-dessous.
- Auteur des commits : `git -c user.name="Lauro Foletti" -c user.email="lauro.foletti@gmail.com" commit`, message en style conventional-commit, **sans** ligne `Co-Authored-By` (décision de Lauro du 19 octobre 2026 : rien de tel sur les PR amont ; la règle vaut pour tous les commits de ce dépôt).

## Pipeline avant toute PR (procédure complète : `docs/pipeline_pr.md`)

En vigueur depuis le 19 octobre 2026, validé le soir même sur six PR (quatre à 100 % de couverture du patch, deux à 100 % hors `main`).

**Trois niveaux** (décision du 20 octobre 2026, `docs/pipeline_pr.md`, section 1) : niveau 1, `make precommit` et la mutation à la main de la règle changée, à chaque changement ; niveau 2, analyse, relecture, ADR, tout ce qui peut révéler un trou, **avant** de lancer la chaîne lourde, têtes gelées ensuite, aucune copie de travail touchée pendant la chaîne ; niveau 3, `make prepr` par tête (avec `make clock`, rejeu des tests qui lisent l'heure) puis `make benches` une fois par lot sur `proto` (`make level3` enchaîne les deux), juste avant la poussée, relancé seulement si le code change. Mutation à la main par `make handmut` (restauration depuis une copie, refus d'un fichier non commis), jamais par `git checkout` (21 octobre 2026). Un trou trouvé pendant la chaîne va dans une liste ; la chaîne repart une fois, à la fin. **Niveau 2, cinq contrôles par classe (21 octobre 2026, après le second tour de revue, 11 points sur 14 trouvables à l'avance) : canari dans `precommit` (aucun test n'atteint un serveur, un embedder ni le cerveau de la machine), `make inventory` (chaque classe listée depuis l'arbre, entrées exportées et RPC typés compris) et `make invcheck FF=<inventaire>` (sortie 1 par élément sans ligne ni test, premier pas de `prepr`), `make diffmain SCENARIOS=docs/pr/<lot>/scenarios` (les mêmes scénarios sur `main` et sur la tête, diff des journaux), promesses des schémas tenues par un test nommé, relecture adverse par un agent neuf sur les têtes gelées (invite fixe, `docs/pipeline_pr.md`, section 1 bis).** Détail : `docs/pipeline_pr.md`, section 1.

1. Le patch est couvert à 100 % de ses lignes atteignables **avant le premier push**, mesuré en local : `make precommit REPO=<copie> BASE=<base>` (gofmt, vet, `-race` des paquets touchés, `patchcov`). Les blocs du corps de `func main()` sont affichés à part, sans bloquer : les déclarer dans une section `## Codecov` du corps de la PR, après `## Breaking Changes` et de même rang (« The N lines left uncovered are inevitable. … »).
2. **Le test s'écrit avant le code** et tombe sans lui. La preuve livrée au relecteur : une mutation à la main par règle qui fait tomber un test nommé, consignée dans `docs/pr/<lot>/failing_first.md`. `make mutate` en plus, survivants lus un à un ; ceux des paquets `main` se rejouent à la main (`gremlins` n'y tue rien).
3. Avant la PR : `make prepr REPO=… BASE=…` (precommit, mutate, suite complète `-race`, éval lexicale), environ 25 min.
4. Le hook `pre-push` du clone (`make hooks`) exécute `precommit` à chaque push. Jamais de `--no-verify`.
5. **Toute PR s'ouvre en brouillon** (`gh pr create --draft`) et passe « ready for review » (`gh pr ready`) seulement quand le rapport Codecov de sa tête montre zéro ligne non couverte, ou exactement les lignes de `main` déclarées quand zéro n'est pas possible. Une PR à amender repasse en brouillon pendant la vérification.
6. Une poussée par lot, après la vérification complète, jamais au fil des rapports Codecov.
7. Code couvrable : `main` réduit à la répartition et à `os.Exit(xCommand(...))`, environnement lu dans des fonctions qui rendent une erreur, chemins d'erreur provoqués par des pannes SQLite déterministes (ligne à `id` NULL, déclencheur `RAISE(ABORT)`, colonne renommée), `rows.Err()` via `eachRow`, garde-fou injouable retiré.
